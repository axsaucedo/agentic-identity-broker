# Speckit Migration Plan: v0.5.0 → v0.8.4

## Context

This repo runs speckit v0.5.0 (initialized 2026-04-23). The latest specify-cli v0.8.4 is
available locally. Four coding agents have speckit setups that need upgrading. Shared
infrastructure (templates, scripts) has been heavily customized and requires a three-way merge.

## Current Inventory

| Agent | Current Location | v0.8.4 Format | Change Type |
|---|---|---|---|
| **opencode** | `.opencode/command/speckit.*.md` (9 files) | Same structure (9 files) | Already v0.8.4 — restore after switch |
| **Claude Code** | `.claude/commands/speckit.*.md` (9 files) | `.claude/skills/speckit-*/SKILL.md` (9 dirs) | Commands → Skills migration (registered integration) |
| **GitHub Copilot** | `.github/agents/*.agent.md` + `.github/prompts/*.prompt.md` (18 files) | Same structure (18 files) | Content update |
| **Codex** | `.codex/prompts/speckit.*.md` (9 files) | `.agents/skills/speckit-*/SKILL.md` (9 dirs) | Prompts → Skills migration |
| **Shared infra** | `.specify/templates/` (6) + `.specify/scripts/bash/` (5) | Same structure, updated content | Three-way merge |

### Version Indicators

- `.specify/init-options.json`: `speckit_version: "0.5.0"`, `integration: "opencode"`
- `.specify/integration.json`: `version: "0.5.0"`, integration: `opencode`
- `.specify/integrations/speckit.manifest.json`: `version: "0.5.0"`
- `.specify/integrations/opencode.manifest.json`: `version: "0.5.0"`, tracks 9 command files + 2 scripts
- `.specify/memory/constitution.md`: v1.9.0 (heavily evolved, NOT at risk — lives in `memory/`, not `templates/`)

### Current Working Tree State

The `.opencode/command/speckit.*.md` files are **staged but uncommitted** (added by the v0.8.4
CLI when it was first run). Their manifest hashes will not match v0.5.0 because they were
generated by v0.8.4. These files must be backed up before `specify integration switch` is run,
as `switch` uninstalls the current integration and deletes its managed files.

## Constraints

- **specify-cli supports only ONE registered integration at a time.** Installing a second fails.
- `specify integration upgrade` updates agent files + manifests but skips shared infrastructure
  unless `--force` is used (which overwrites without merging).
- `specify integration switch` **uninstalls** the current integration first, deleting its
  manifest-tracked files. The opencode command files will be deleted if not backed up.
- Templates have been customized across 10+ commits (constitution amendments, entity ID boilerplate
  phases, testing mandates, design system rules). `--force` would destroy these customizations.

## Strategy

- **Claude Code** = registered integration (gets `specify integration upgrade` support going forward)
- **opencode, copilot, codex** = manually maintained using reference files
- **Shared infrastructure** = three-way merge preserving our customizations while incorporating
  upstream improvements
- **Reference files** generated via `specify init --here` in temp directories at `/tmp/speckit-upgrade-ref/`
- **`CLAUDE.md`** = already resolved: `CLAUDE.md` exists with `@AGENTS.md` (Claude include syntax)
- **`agent-file-template.md`** = keep as local extension (used by `update-agent-context.sh`)
- **`.specify/workflows/`** = adopt from v0.8.4 reference

## Execution Steps

### Step 0: Preparation

1. Create branch `chore/speckit-upgrade-0.8.4` from current HEAD.

2. Clean and regenerate v0.8.4 reference files for all 4 agents:
   ```bash
   # Clean stale empty dirs from previous run
   rm -rf /tmp/speckit-upgrade-ref/
   mkdir -p /tmp/speckit-upgrade-ref/{claude-ref,opencode-ref,codex-ref,copilot-ref}

   # Generate v0.8.4 reference files (use --here and --force for non-empty dirs)
   cd /tmp/speckit-upgrade-ref/claude-ref   && specify init --here --integration claude   --force --no-git
   cd /tmp/speckit-upgrade-ref/opencode-ref && specify init --here --integration opencode --force --no-git
   cd /tmp/speckit-upgrade-ref/codex-ref    && specify init --here --integration codex    --force --no-git
   cd /tmp/speckit-upgrade-ref/copilot-ref  && specify init --here --integration copilot  --force --no-git
   ```

3. Back up the opencode command files before Step 1 deletes them:
   ```bash
   cp -r .opencode/command /tmp/speckit-upgrade-ref/opencode-backup
   ```

4. Identify the git commit that introduced `.specify/templates/` (base for three-way merge):
   ```bash
   git log --oneline --diff-filter=A -- '.specify/templates/' | tail -1
   # → 0016c595 feat: Add templates for project documentation and task management
   ```

### Step 1: Switch registered integration opencode → claude

```bash
specify integration switch claude
```

**What this does:**
- Uninstalls the opencode integration → **deletes** the 9 `.opencode/command/speckit.*.md` files
  (tracked in opencode manifest) and the integration scripts
- Installs Claude integration → creates `.claude/skills/speckit-*/SKILL.md` (9 skill dirs)
- Updates `.specify/integration.json`, `.specify/init-options.json`, manifests

**Post-step verification:**
- Confirm `.claude/skills/` contains both `aws-crypto-go` (our custom skill) and 9 `speckit-*` dirs
- Confirm `.opencode/command/speckit.*.md` files are gone (they will be restored in Step 3)
- Review any changes to `AGENTS.md` or `CLAUDE.md`

**Commit:** `chore(speckit): switch registered integration to claude code`

### Step 2: Remove stale Claude commands

Delete `.claude/commands/speckit.*.md` (9 files) — these are v0.5.0 command-style files,
now replaced by the skills installed in Step 1.

```bash
rm .claude/commands/speckit.*.md
```

**Commit:** `chore(speckit): remove stale claude command files replaced by skills`

### Step 3: Restore opencode commands

The opencode files deleted in Step 1 were already v0.8.4 content. Restore from backup:

```bash
cp /tmp/speckit-upgrade-ref/opencode-backup/*.md .opencode/command/
```

**Do not** copy from the opencode ref dir — the backed-up files are identical in content and
were already generated by v0.8.4. The opencode integration is now manually maintained;
no manifest tracks these files.

**Commit:** `chore(speckit): restore opencode commands as manually-maintained v0.8.4 files`

### Step 4: Update copilot agents and prompts

1. Replace all 9 `.github/agents/speckit.*.agent.md` with v0.8.4 versions from
   `/tmp/speckit-upgrade-ref/copilot-ref/.github/agents/`.
2. Replace all 9 `.github/prompts/speckit.*.prompt.md` with v0.8.4 versions from
   `/tmp/speckit-upgrade-ref/copilot-ref/.github/prompts/`.
3. Check if v0.8.4 adds `.github/copilot-instructions.md` (repo-root level). If so, inspect
   for overlap with `.github/agents/copilot-instructions.md` (agent-level, project-specific).
   These serve different purposes — keep both, merging any speckit-specific additions into
   the existing agent-level file if needed. Check for a `.vscode/` dir in the copilot ref
   and adopt if present.

**Commit:** `chore(speckit): update copilot agents and prompts to v0.8.4`

### Step 5: Migrate codex from prompts to skills

1. Remove old `.codex/prompts/speckit.*.md` (9 files):
   ```bash
   rm .codex/prompts/speckit.*.md
   ```
2. Copy `.agents/skills/speckit-*/` (9 dirs) from
   `/tmp/speckit-upgrade-ref/codex-ref/.agents/skills/`:
   ```bash
   cp -r /tmp/speckit-upgrade-ref/codex-ref/.agents/skills/speckit-* .agents/skills/
   ```

**Commit:** `chore(speckit): migrate codex from prompts to skills (v0.8.4)`

### Step 6: Three-way merge of shared infrastructure

For each of the 11 files in `.specify/templates/` (6) and `.specify/scripts/bash/` (5):

1. Extract **base** (v0.5.0 original) from git:
   ```bash
   git show 0016c595:.specify/templates/<file> > /tmp/speckit-upgrade-ref/base/<file>
   ```
2. **Ours** = current repo version
3. **Theirs** = v0.8.4 from `/tmp/speckit-upgrade-ref/claude-ref/.specify/templates/<file>`
   (use claude-ref as canonical source for shared infra)
4. Three-way merge:
   ```bash
   diff3 -m ours base theirs > merged
   ```
5. Review and resolve conflicts manually.
